# Technion Smart Vibe
מתכנן מערכת שעות לסטודנטים בטכניון: חיפוש קורסים אמיתיים, פרטי קורס וקבוצות, מפת קדמים עם AND/OR, בחירה הנשמרת בדפדפן, תכנון ידני, זיהוי חפיפות ויצירת עד עשר מערכות המדורגות לפי העדפות.

## הרצה ב־WSL
Node 22 מומלץ. אם nvm מותקן:
```bash
cd ~/projects/technion-smart-vibe
source ~/.nvm/nvm.sh
nvm use
npm install
npm run dev
```
פתחו http://localhost:3000. בדיקות סביבה קצרות: `node --version`, `npm --version`, `git --version`. מומלץ לפתוח את התיקייה באמצעות `code .` בתוך WSL עם התוסף Microsoft WSL.

## בדיקות וייצור
```bash
npm test
npm run lint
npm run typecheck
npm run build
npm start
```

## שימוש
חפשו שם בעברית או מספר קורס (234124 וגם 02340124 נתמכים). הוסיפו עד 10 קורסים. במערכת שלי ברירת המחדל היא שילוב חופשי: בחרו הרצאה, תרגול ומעבדה בנפרד, גם אם מקורן בקבוצות רישום שונות. כל המפגשים השבועיים של האפשרות שנבחרה נשמרים יחד. סמנו ״לשמור על קבוצות הרישום״ כדי לבחור את כל המפגשים כחבילה לפי הקבוצה במקור. אפשרויות מותרות למנוע האוטומטי נבחרות בנפרד לכל סוג במצב חופשי, או לפי קבוצת רישום במצב קבוצות. הגדירו חשיבות 0–5, וסמנו חובה רק לתנאים שאין עליהם פשרה. לחצו ״יצירת מערכות חכמות״, עברו בין התוצאות, ושמרו אפשרות כמערכת הידנית שלכם.
בחירת הקורסים, שיטת השילוב, קבוצות ידניות, מפגשים ידניים, הגבלות קבוצות/מפגשים, העדפות וערכת הצבעים נשמרות ב־localStorage לפי סמסטר. תוצאות החיפוש האוטומטי נשמרות בזיכרון עד לרענון; אפשר לייצר אותן מחדש.

## ארכיטקטורה
Next.js App Router + React + TypeScript + Tailwind CSS 4. ללא מסד נתונים או התחברות.
- `app/`: דפי חיפוש, פרטי קורס, קדמים, תכנון ותוצאות; API לשליפת קורסים וליצירת מערכות.
- `components/`: ממשק RTL רספונסיבי, בחירה, העדפות, עץ קדמים ולוח שבועי.
- `types/course.ts`: טיפוסי הקורס, המפגש, האפשרות והמערכת.
- `lib/data.ts`: קריאת snapshot פעם אחת בתהליך, Map לפי מזהה ואינדקס חיפוש.
- `lib/normalize.ts`: נרמול מספרים, שעות ושורות מפגש; קבוצה ומס׳ מפגש הם שדות נפרדים.
- `lib/components.ts`: אפשרויות הרצאה/תרגול/מעבדה לפי סוג ומספר מפגש, איחוד שיעורים משותפים ובחירה ידנית במצב חופשי.
- `lib/prerequisites.ts`: parser מחמיר עם AST וקדימות AND מעל OR. תחביר לא מוכר שומר את הביטוי המקורי ומוצג בממשק.
- `lib/schedule.ts`: backtracking של קבוצות שלמות או של אפשרויות מפגש עצמאיות לפי שיטת השילוב, pruning של חפיפות ותנאים קשיחים, שמירת Top 10, מדדים וניקוד 0–100.
- `lib/store.ts`: אחסון מקומי עם בדיקת מבנה, תמיכת רענון וסנכרון לשוניות.
- `data/`: נתוני המקור, מטא־נתוני סמסטר ורישיון.
- `tests/`: בדיקות יחידה ונתונים אמיתיים; `e2e/`: בדיקות דפדפן.
- `scripts/`: עדכון snapshot.

ב־API אין אפשרות לספק מפגשים מזויפים: המנוע מקבל מספרי קורסים וקבוצות בלבד ומחזיר נתונים מה־snapshot בצד השרת. דף החיפוש מקבל רק תקצירי קורסים. פרטי המפגשים נטענים עבור הקורסים הנבחרים בלבד.

## דיוק ומגבלות
במצב קבוצות, אפשרות היא כל השורות עם אותו שדה ״קבוצה״. במצב חופשי בוחרים בנפרד אפשרות אחת מכל סוג מפגש אקדמי. אפשרות מפגש כוללת את כל השורות של אותו סוג ואותו ״מס.״, עם הסרת כפילויות של הרצאות משותפות. פעילויות חינוך גופני נחשבות חלופות תחת סוג ״מפגש״. המנוע מחפש בין אפשרויות מפגש בלי לבנות מראש את כל המכפלה הקרטזית. ״מס.״ מזהה מפגש משותף; לא מסיקים שיוך באמצעות חלוקה בעשר. מפגשים חוזרים בכמה ימים נשמרים כולם. כפילות מדויקת באותה קבוצה מוסרת. שורות זמן חסרות נשמרות בפרטים אך מונעות שימוש אוטומטי בקבוצה. קבוצה עם חפיפה פנימית אינה זמינה למנוע. חפיפות משתמשות באינטרוולים חצי פתוחים: מפגש המסתיים בדיוק כשהבא מתחיל מותר. שישי ושבת מופיעים בלוח כשיש מפגשים; ״לפחות יום פנוי״ נספר בראשון עד חמישי.
מפת קדמים עוצרת במחזור, בעומק 6 או לאחר 100 צמתים; ניתן להמשיך מדף קורס. רפרנס לקורס שלא מוצע בסמסטר מוצג עם הודעה.
החיפוש מוגבל ל־200,000 צמתי חיפוש, עד 10 קורסים ועד 10 תוצאות. החיפוש שומר את עשר המערכות המובילות מבין כל המערכות שנבדקו, ומציג הודעה ברורה אם לא הסתיים. הניקוד הוא 100 פחות ממוצע משוקלל של קנסות מנורמלים: דקות בבוקר/בערב, זמן ביום המועדף כחופשי, חלונות, ימים בקמפוס והעדפות מרצים.
התכנון מונע חפיפות בשיעורים. שמירה על שיוכי קבוצות מופעלת רק כאשר ״לשמור על קבוצות הרישום״ מסומן. במצב חופשי מגבלות קבוצות שמורות אינן מגבילות את אפשרויות המפגש, ולהפך. בחירות ידניות בשני המצבים נשמרות בנפרד. תנאי קבלה, מכסות, הגבלות אוכלוסייה המופיעות בהערות ובחינות אינם מאומתים אוטומטית. בדקו את הערות הקורס והסירו קבוצות שאינכם זכאים להן לפני יצירה. התוכנה אינה כלי רישום רשמי.

## פרסום ב־Vercel
1. צרו repository ריק ב־GitHub, ואז הריצו בתיקיית הפרויקט:
```bash
git remote add origin https://github.com/YOUR_USER/technion-smart-vibe.git
git push -u origin main
```
2. ב־Vercel בחרו Add New → Project וייבאו את המאגר.
3. השאירו Framework: Next.js, Root Directory: ./, Node.js: 22.x, ואז Deploy.
אין צורך במשתני סביבה. קובץ הנתונים נכלל בפרויקט. URL ציבורי יתקבל רק לאחר החיבור לחשבון ו־Deploy.

## בדיקות דפדפן
לאחר build: `npm run test:e2e`. בהתקנה חדשה הורידו Chromium באמצעות `PLAYWRIGHT_BROWSERS_PATH=.browser-cache npx playwright install chromium`. אם חסרות ספריות ב־Linux, השתמשו ב־`npx playwright install-deps chromium`. השרת לבדיקה מופעל ונסגר אוטומטית.
